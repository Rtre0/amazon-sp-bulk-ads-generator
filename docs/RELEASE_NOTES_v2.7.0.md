### 本次重点：一眼看出哪些商品还没开广告

在商品表里直接标出每个父体的状态：

| 显示 | 含义 |
| --- | --- |
| 🟢 已开启 | 有正在投放的广告活动 |
| ⚪ 已暂停 | 开过但停了（暂停 / 归档都不算开启） |
| ⚪ 未开启 | 完全没建过活动 |

勾 **只看未开** 就能把「已暂停 + 未开启」一起筛出来，逐个去开广告，
不用再去赛狐后台一个个核对。首次查询大店铺约 20 秒，之后有 10 分钟缓存，
可点 `↻` 刷新。

真实店铺实测（521 个父体 / 2204 个活动）：**已开启 173、已暂停 267、未开启 81**；
筛选后表格里已开启数量归零，浏览器无报错。

## 3. 从旧版升级

```bash
# 1) 停掉正在跑的服务，备份项目内的 data/ 与 config/（如果有）
# 2) 拉新代码
git pull --ff-only origin main
# 3) 补装新依赖（新增了定时任务与浏览器自动化相关组件）
venv\Scripts\python.exe -m pip install -r requirements.txt
# 4) 推荐：把数据与 Cookie 搬到项目外
venv\Scripts\python.exe tools/migrate_to_external.py --move
#    之后用「启动（数据外置）.bat」启动即可
# 5) 重新登录赛狐（Cookie 一般 5 天过期，需人工输一次图形验证码）
# 6) 验证
bash tests/run_all.sh      # 应显示 PASS 291 / FAIL 0
```

**升级后建议确认**

- [ ] 健康检查里版本号是 `2.7.0`，数据目录指向期望位置
- [ ] 上传一份 Excel 走离线路径，能正常下载 Bulk 表（旧能力没被改坏）
- [ ] 同步商品后载入本地商品库，缩略图不是白块
- [ ] 「广告状态」列有值，勾「只看未开」能过滤
- [ ] 手动广告「查询并同步」的日期范围与所选一致
- [ ] 「接口直接创建」先用**单店铺 + 小批量**试一次

**兼容性**：旧版功能全部保留；不配赛狐登录态也能照常走离线 Excel 路径。
本次没有删除或改写已有数据字段，Cookie 文件的旧格式会自动升级。

**回滚**：`git checkout v10.0.0`（或回到 10 月 30 日那个提交）即可。
本地数据不会被删除；若已把数据外置，取消外置设置就能让旧版回到项目内目录。

## 5. 已知限制

1. 赛狐 Cookie 约 5 天过期，登录页强制图形验证码，无法全自动登录；失效容易与「没数据」混淆。
2. 搜索词必须按店铺分别拉取，全账号一次拉会漏 5%~19% 的行。
3. 广告状态首次查询耗时随店铺规模增长（约 20 秒 / 2200 活动），已有 10 分钟缓存。
4. 「接口直接创建」会真的在赛狐后台建活动，属于写操作，首次请小批量验证。
5. 生成的 Bulk 表是「官方 31 列 + 1 个辅助 ASIN 列」共 32 列，不要在表里手工增删列。
6. 内部运营工具，未附开源许可证；词库属业务资产，请勿外传。
